# KjobsUltimate V3.16.2 — Wither Armored Fix

## Cause exacte

Le test `/kjobs testhud` affiche 75 %.

À 75 %, le faux Wither est au-dessus de la moitié de sa vie et n'est pas dans
son état armored.

La bossbar réelle du screenshot était à :

```text
190 / 800 = 23,75 %
```

Donc le faux Wither était sous 50 % de vie. Le client Minecraft 1.8 active
alors son comportement armored et produit les particules blanches.

Ce n'était donc pas une régression de `setInvisible(true)`.

## Pourquoi on ne force pas la vie au-dessus de 50 %

La longueur de la bossbar est directement dérivée de la vie de l'entité.

Forcer par exemple une progression réelle de 23 % à 51 % ferait disparaître
les particules armored, mais afficherait une barre fausse.

V3.16.2 conserve donc une progression 100 % fidèle.

## AUTO adaptatif

Au-dessus du seuil :

```yaml
auto_distance: 36.0
auto_vertical_offset: -7.0
```

Sous le seuil :

```yaml
armored_threshold: 0.50
armored_distance: 28.0
armored_vertical_offset: -18.0
```

L'entité reste devant le joueur pour que la bossbar 1.8 reste affichée, mais
elle descend beaucoup plus lorsque les particules blanches existent.

## Ajustement

Si les particules blanches restent visibles :

```yaml
armored_vertical_offset: -20.0
```

puis éventuellement :

```yaml
armored_distance: 24.0
armored_vertical_offset: -22.0
```

Si la bossbar disparaît, réduire la profondeur :

```yaml
armored_vertical_offset: -15.0
```
